# 学情可视化展板

静态 HTML 应用。个人分析、小题分析、趋势、班级对比、智能分析和综合诊断沿用原来的分析规则；座位模块的统计与互补口径见下文。

## 数据入口

在“上传管理”中，通过三个并列区域的“选择总表文件”“选择小题表文件”“选择PDF/MD试卷”导入对应文件。页面恢复原来的独立卡片、分类颜色与按钮，三个入口共用新版导入队列、解析、匹配和保存流程。总表与小题表支持 `.xlsx`、`.xls`、`.csv`，可以一次选择多个文件；同名同类型文件在解析成功后替换原文件，解析失败保留当前数据。

总成绩表模板可在同一位置下载。表头支持 1–3 行及 Excel 横向合并单元格；姓名、班级、分数、等级和题号保持原来的识别方式。每个文件单独检测表头，多文件解析完成后统一合并。小题满分沿用文件表头，不从最高得分推算。

数字与等级使用统一格式：全角数字转为数字，保留零分，空白和占位符不作为有效单科成绩；等级统一大小写。班级 `801`、`01班`、`一班` 等按同一班级匹配，显示为 `01班`；学生按“姓名 + 班级”匹配，跨班重名保留为不同学生。主成绩表的单科分数、等级和排名优先于小题表附带的同类字段。

保存后自动进入“新建批次”。批次包含原始表格、合并表头、小题元数据与原始 PDF 字节，刷新后仍可重新调整表头或解析 PDF。旧 JSON/base64 批次仍能读取；旧版本未保存的原始表格无法凭空恢复，但不会因为重新调整表头而清空已解析的成绩。

## 共用模块

- `app-core.js`：输入规范、学生身份、PDF 字节、顺序存储队列、工作簿读取、图表创建/释放和节流缩放。
- `spreadsheet-worker.js`：在后台线程读取 Excel / CSV；直接打开本地 HTML 或 Worker 不可用时回退到相同格式的主线程解析。
- `app.css`：集中维护颜色、控件、字号层级与字体。正文基准 14px，页面/控件/图表使用同一中文字体栈；数学公式保留数学字体。Word 普通文字统一为微软雅黑。
- `reports.js`：个人、班级、单科、进退步、临界预警、学科关联和座位图文报告，共用报告图表规范。
- `class-comparison.js`：班级均分、热力图、等级/名次分布、箱线图及相关导出。
- `seating.js`：座位数据模型、布局交互、快照与事件绑定。
- `seating-data.js`：本次班内成绩统计、互补判断、学生变动匹配、排位校验和持久化快照。
- `index.html`：页面、数据导入、小题分析、趋势与综合诊断等剩余业务。三个模块在页面 DOM 就绪后、主脚本执行前按顺序加载，下载通过 preload 并行进行；沿用经典脚本，兼容直接打开 HTML。

模块拆分时将 `index.html` 从 17,849 行、1,010,749 字节调整为 11,835 行、649,960 字节。主要通过按业务拆分实现，并清理 29 处图表创建前的重复释放。业务模块没有删除或压缩成难以维护的代码；此处行数减少不等于项目总代码减少同样数量。

成绩表单文件上限 50 MB，后台解析超时为 60 秒；错误会显示在导入状态中。保存失败不会把页面切换到空白新批次，删除失败会恢复原批次列表。导入、恢复和保存期间禁用会改变当前批次的控件，程序切换批次后的旧导入结果也不会写回新批次。

## 座位保存与恢复

每个班级独立保存排位、学生标签、固定/关注状态、禁用空位、标签显示和已应用的高级设置。同一班级切换考试或刷新成绩时，保留人工排座，更新本次成绩统计；新加入的学生填入空位，离开的学生释放座位，原来主动移到待分配的学生继续保留在待分配区。

每次有效改动都自动追加快照，包括手动拖动、标签/状态调整、轮换、智能排座、设置应用和清空排位。历史不再限制为最近十份，也不会因刷新或关闭浏览器删除。列表先显示最近 50 份，可展开更早记录；每份记录注明时间、改动原因和考试批次。恢复或导入排位前保存当前状态，恢复后再追加一份快照，因此不会覆盖后续历史。

改动先同步写入本地待保存记录，再按顺序写入 IndexedDB；浏览器在异步写入完成前关闭，重新打开时重放尚未完成的记录。保存失败会显示真实状态。不同项目的座位档案按页面路径隔离，旧版可确定所属班级的快照自动迁移。保存属于当前浏览器和站点；换设备或清除站点数据前可使用“导出复原JSON”，之后通过“导入复原JSON”恢复。Excel 用于查看排位和统计，JSON 用于恢复设置。清空排位保留学生与所有历史。

## 座位成绩与学科互补口径

统计范围固定为当前考试、当前所选班级，学生按姓名和规范化班级匹配。历史考试仅用于展示趋势，不参与本次梯度或互补判断；原年级名次可供查看，不能直接除以班级人数。

每科优先按本次有效得分在班内排序。零分有效；空白、缺考、占位符不是零分，也不标成薄弱。整班该科都没有有效分数时，才依次选择原班级、年级、学校名次的一种来源，在当前班内重新排序；明确标记缺考的记录不进入名次回退。某科已有得分时，不把仅有名次但缺分的学生混入得分样本。

同分采用并列名次，例如 1、1、3。相对位置使用同分组的平均位置：`（同分组起始索引 + (同分人数 - 1) / 2）/（有效人数 - 1）×100%`，索引从 0 开始；0% 表示最好，100% 表示最末。全班同分时均为 50%，单个有效成绩时相对位置为数据不足。同分学生采用同一梯度，不人为拆分。

整体梯度优先使用总分的班内相对位置，每 12.5 个百分点一档，分为 L1–L8。无可用总分时，对有至少两个有效记录的单科相对位置取等权平均，再在班内排序；学生必须具备所有参与科目的有效相对位置，缺科则不生成综合梯度。综合科目及总分本身不重复计为单科，也不直接相加不同满分的原始得分。

同一科中，一人的相对位置 ≤20%、另一人 ≥75%，才记录该科的互补和帮扶方向。缺失数据不形成互补。这是相对位置阈值，并非强行选出固定人数的前 20% 和后 25%。优化器、学生详情、帮扶图、座位图文报告与 Excel 共用该判断。梯度配对分值是整体层次的排座权重，与学科互补科数分别显示；行为标签、固定位置和禁用空位仍作为排座限制。恢复旧排位时重新计算本次成绩，不把旧成绩带回当前判断。

## 验证

应用运行不需要安装 npm 依赖。开发回归测试可执行：

```sh
npm install
npm test
npx playwright install chromium
npm run test:browser
```

已有 Chromium 时可设置 `CHROMIUM_EXECUTABLE`；浏览器启动参数可用 `CHROMIUM_ARGS` 提供 JSON 数组。

测试覆盖输入格式、班级与重名身份、PDF 多种旧格式、后台/回退解析、多文件一次合并、失败与重复导入、保存/刷新恢复、原始表头保留、8 个功能页、热力图三种视图与 PNG 导出、进退步模型、存储写入顺序和旧批次迁移。上传页面另外验证三个按钮的文件选择、导入期间按钮禁用，以及桌面并列/窄屏堆叠布局。本轮补测模块下载延迟、7 类图文报告实际生成、座位交互与快照，以及打印前后事件。

座位专项测试覆盖同分、零分/缺考、原始排名回退、跨班重名、总分缺失、新生/离班与待分配保留、20 次以上快照、跨班/跨考试恢复、固定/禁用位置轮换、实际优化器、Excel/报告统计一致、JSON 导出导入、数据库写入失败，以及关闭整个浏览器后恢复连续未完成写入。

本次本地 Chromium 基准：同一组 5000 名学生（无班级的唯一姓名，单科与一小题）连续合并三次，原版耗时 1244 / 1392 / 1470 ms，优化后 68 / 55 / 44 ms。该结果包含学生合并、搜索索引、名单和备用排名，主要反映消除逐行扫描姓名表的收益，不代表所有页面或数据规模的固定性能提升。
